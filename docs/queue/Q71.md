# Share one client budget across resource types, or state it per type

`cmd/main.go` sets `QPS` and `Burst` on the rest config, and each resource's REST client gets its own token bucket from them, so QPS 50 does not bound the controller's total writes. The design's rate-limit section said it did until Q50.

The reviewer of Q50 measured this through a real manager on envtest 1.37, at `QPS 50, Burst 100`, with 60 nodes × 8 pods and one `dryRun` flip:

| Client | Resizes | Drain | All PATCH requests | Average | Peak in 1s |
|---|---|---|---|---|---|
| As shipped | 480 | 8.6s | 960 | 111/s | 298/s |
| With one shared `rest.Config.RateLimiter` | 480 | 27.5s | 1440 | 52/s | 148/s |

The shared run's extra 480 are inferred to be annotation rewrites, and that row measures the limiter alone rather than a full suite with it. The bucket assignment comes from reading `vendor/sigs.k8s.io/controller-runtime/pkg/client/client_rest_resources.go` and `vendor/k8s.io/client-go/rest/config.go`; nobody has read which bucket `writePodStatus` draws from.

Decide whether a shared limiter is worth the slower drain, then either share it or document the budget as per type in `docs/runbook.md`. Sharing it would also put each resize behind status annotation writes in one queue, so measure that before choosing.
