# Stop the controller crash-looping when webhook.enable=false

Installing the chart with `webhook.enable=false` and `certmanager.enable=false` leaves the controller crash-looping. The chart stops passing the certificate path but never tells the binary to skip the webhook server, so it starts anyway and exits on the missing certificate.

Measured 2026-11-04 on a kind v1.35.0 cluster (worker with 18 allocatable CPUs), image built from 1be389d, webhooks off. With the operator chart at those values, the rollout timed out after 180 seconds, and the pod reached 7 restarts in 14 minutes with `open /tmp/k8s-webhook-server/serving-certs/tls.crt: no such file or directory`. Only this flag combination was run. Setting `ENABLE_WEBHOOKS=false` through `extraEnv` is the workaround, which is how the other audit items were measured.

Have the chart set `ENABLE_WEBHOOKS=false` whenever `webhook.enable` is false, and add a check that fails if that case stops rendering it. `scripts/helm-render-matrix.sh` is the likely home.

`cmd/main.go:212:os.Getenv("ENABLE_WEBHOOKS")` is the switch, and `charts/kube-headroom/templates/deployment.yaml:58:--webhook-cert-path` is the value the chart gates today.
