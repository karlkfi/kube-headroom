# Fix tenants.html scrolling sideways on phones

The landing page `website/landing/tenants.html` is 443px wide at both a 320px and a 390px viewport, so it scrolls sideways on a phone. Measured 2026-11-05 by loading each page of the built site (`make site-landing` plus the VitePress build) at several viewport widths and comparing `documentElement.scrollWidth` to the viewport. `index.html`, `faq.html` and `404.html` fit at both widths.

The widest element is the "See why your ceiling is what it is" item under "The practical bits" (`.howto-item`, right edge at 443px). Its `<pre>` holds a long unbroken `kubectl get pod … -o jsonpath` line. Because the item is a grid item with the default `min-width: auto`, it stops the single-column `.howto` grid from shrinking below that line.

The independent reviewer of Q63 confirmed the fix at 320px on a built site ([#117 comment](https://github.com/karlkfi/kube-headroom/pull/117#issuecomment-6673245431)). The page measured 444px wide. Hiding `.howto` or `.howto-item` brought it down to 320px, and so did adding `min-width: 0` to `.howto-item` and `overflow-x: auto` to its `<pre>`. Hiding the hero `svg.day-art` changed nothing, so the SVG is not the cause.

WCAG 1.4.10 sets 320px as the width content must reflow to. Do not hide it with `overflow-x: hidden` on the page, which clips the text instead of fixing the layout.
