# Handle pods with pod-level resources, whose resize 1.35 refuses

On Kubernetes 1.35 a managed pod with `spec.resources` set never gets a new CPU limit, on any pass, and the controller logs an error for it each time. Every other pod on the node still converges, because a failed pod no longer ends the pass, but this one retries with backoff indefinitely.

Measured by the independent reviewer of the Q49 change on a kind v1.35.0 cluster, on a pod with memory set at pod level. The controller and a direct `kubectl patch --subresource resize` got the same refusal:

```
Pod "l-podlevelmem" is invalid: []: Forbidden: resize of pods with pod-level resources is forbidden when InPlacePodLevelResourcesVerticalScalingEnabled feature gate is disabled
```

envtest 1.37 accepts the same resize, so `internal/controller/node_controller_qos_test.go:164:pod-level resources set the class` passes without showing what 1.35 does, and no spec in the repo can reproduce this.

A likely fix is an eligibility gate that leaves these pods unmanaged, which nobody has tried. It would also give up resizing them on versions that allow it, and whether a real kubelet applies the resize on 1.37 has not been measured.

**Measure:** on a kind cluster at 1.37, whether a pod with pod-level resources resizes, and then choose between a gate for all versions and one keyed on the server's version.
