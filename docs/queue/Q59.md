# Skip pods under a limit-managing VPA, or drop the unused VPA RBAC

The chart grants read access to VerticalPodAutoscalers and nothing uses it, against the project's least-privilege claim. The design also promises a VPA-exclusion check in Phase 2. A VPA in its default `RequestsAndLimits` mode fights the controller over the same limit, and today only the docs warn about it.

**Ask:** what turns on Karl is whether Phase 2 still includes this check. If it does, detect those pods and skip them with an event. If it does not, remove the RBAC marker, regenerate with `make manifests generate helm-sync`, and record the decline in the design. Read from the code and not run.

`internal/controller/headroomconfig_controller.go:74:verticalpodautoscalers` and `docs/design.md:426:VPA-exclusion check` are the sites.
